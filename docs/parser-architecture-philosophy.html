Architecture Philosophy · EPUB Parser

从「尽力解析」到
「守恒、协商、溯源」

一次关于解析器底层哲学的提案：如何让「丢内容」从
「可能发生且无人知晓」变成「结构上不可能」。

解析器的安全性，不应来自每个分支都记得上报，
而应来自结构上不允许不上报。

00缘起：一个静默的洞

在给建议之前，我们先回到证据。现有架构已经有一条明确信条——绝不静默丢内容，并且用 diags 分级来承载它。但在真实数据里，这个信条被绕过了。

实测证据 · 自控力.epub

  • 目录有 68 个条目，最终只产出 57 个章节。
  • 其中 10 个文件同时存在「带锚点」与「不带锚点」的目录条目。
  • 切分器只保留带锚点的条目工作，那 10 个无锚点条目被静默丢弃。
  • 它们所代表的「锚点之前的正文」——例如 每当我提到自己在讲授一门关于意志力的课程时……——没有出现在任何产出中。
  • 而这一整本书跑完，诊断数为 0。

请注意这件事的性质：这不是「忘了写一行 pushDiag」。代码里没有任何一个「决定丢弃内容」的分支，因此也就没有任何地方「应当」上报。内容是被算法的结构吃掉的——一次看起来毫无恶意的 entries.filter(e => e.fragment) 窄化了工作集，副作用就是丢弃。

这就是哲学层面的破洞：diags 是一套劝告式（advisory）机制——它依赖每个分支自觉上报；而真正危险的丢失，恰恰发生在「没有人觉得自己丢了东西」的地方。

01根本矛盾：两种不完整的投影

要设计更安全的架构，先要看清我们到底在做什么。

一本 EPUB 给我们的是同一本书的两种不完整投影：

  • 目录（nav / NCX）：表达了「作者认为的结构」，但只有标题和一个地址，本身没有内容。
  • 正文（spine XHTML）：有全部内容，但结构与目录并不保证对齐——锚点 id 可能根本不存在。

解析的本质，是在这两种投影之间做对齐。而现实是：资治通鉴 的 290 个文件里一个 id 都没有，目录里写的 chapter_1 在正文中根本不存在——对齐彻底失败，290 章全部退化为「整文件」。

于是两个目标在此正面冲突：

冲突

「尽量还原目录结构」（要求按锚点精细切分） 与 「绝不丢内容」（锚点不可靠时只能整文件兜底）。
当前架构用二分法处理：命中精确切分，否则整文件。它保住了内容，却丢掉了结构，而且两者都没有被度量、没有被上报。

02三条第一原则

不是加更多日志，而是换一套不变量。我提议三条原则，它们共同把「安全」从约定变成结构。

壹
Conservation

守恒：解析即记账

输入是可数的，输出就必须能平账。每一个输入单元（一个目录条目、一个顶层 DOM 节点）在流程结束时，必须拥有且仅有一个去向（disposition）：

已产出 ／ 已合并进某产出 ／ 按规则豁免（如 <script>、远程图片，附理由）。

关键不在于「记录」，而在于：由系统在终局校验覆盖率，不平账就失败。不允许存在未登记的去向。

类比：复式记账。每一笔内容的流转都要有对应分录，期末必须试算平衡——余额对不上就是 bug，而不是「可能忘了记」。
贰
Negotiated Alignment

协商：用降级阶梯替代成败二分

不要用「命中 / 未命中」这种二分。对齐是一场协商，应当有一条显式的、逐级让步的阶梯：

L0 精确 id 命中 → L1 归一化后命中（大小写／空白／URL 解码）→ L2 标题文本语义匹配（目录标题 ≈ 正文中某个标题）→ L3 位置序号匹配（目录顺序 ≈ 标题出现顺序）→ L4 整文件兜底。

更重要的是：「实际达成第几层」必须是一等输出，随结果上报。我们现在是 L0 直接跳 L4，290 章的粒度在无人知晓的情况下蒸发。

类比：不是「地址找到了／没找到」，而是「我们用哪种方式找到了它，可信度多少」——诚实地报告对齐质量，而非成败。
叁
Provenance

溯源：每个产出都携带来源坐标

每个产出单元都应携带不可变的来源坐标：{ 文件, 跨度, 来源目录项, 对齐层级 }。

有了它，「有没有丢内容」从一次代码审计变成一次查询；定位问题从猜测变成直达；用户甚至可以看到「这一章是按标题猜出来的，可信度中等」。

类比：学术引用的出处标注。没有出处的结论不可信；没有来源的内容单元不可审计。

03架构形态

把三条原则落成具体的形状。核心的一句话：用「选区」替代「切片字符串」。

当前各层之间传递的是序列化后的 HTML 字符串——每跨一次边界，就要重新解析一次，且原文档的上下文（相邻的兄弟节点）永久丢失。若改为传递针对同一份不可变文档的选区（range），则：只解析一次、没有有损序列化、随时可以回看上下文、覆盖率天然可算。

04对照

维度现状提议
安全模型劝告式：各分支自觉上报结构式：守恒审计，不平账即失败
对齐失败二分：命中 / 整文件兜底L0–L4 显式阶梯，逐级让步
失败可见性依赖分支写日志（本次为 0 条）覆盖率可测量，缺失必然暴露

05它如何消灭那个洞

把原则放回那个真实的 bug 上检验。

在新架构下，entries.filter(e => e.fragment) 这种窄化操作不会「静默生效」：那 10 个无锚点条目会在账本里变成没有 disposition 的输入单元，锚点之前的正文变成未被任何选区覆盖的文档区间。

审计器在终局测量覆盖率时立即发现 < 100%，报 fatal 而非 warning。于是：

性质变化

「丢内容」从 可能发生且无人知晓，变成 一旦发生必然被拦截。
修复它的压力不再是「开发者的细心」，而是「系统的不变量」。

同理，资治通鉴 的 290 次退化为整文件，也不再是一条被压扁的 warning，而是上报为对齐层级分布：L4 占 100%——这本身就是对用户最有价值的信息：「这本书结构还原度低，但内容 100% 保留」。

06代价与权衡

任何架构提案都必须诚实标价。以下是真实的成本。

  • 内存：选区模型要把 DOM 保留到审计完成。可通过「按文件作用域释放 + 引用计数」缓解，但对超大书仍有峰值压力。
  • 复杂度：新增账本与审计器两个组件；选区要处理跨节点边界（选区起点在某个文本节点中间）。
  • 收益不均：对本来就很规整的书（如 TheEconomist，0 个受影响文件）几乎零收益。收益高度集中在畸形／古老／工具生成的 EPUB——而那恰恰是最需要安全的场景。
  • 性能不是问题：实测 11MB / 290 章的 资治通鉴 全流水线仅 2.1 秒，完全负担得起额外的对齐尝试与审计开销。所以：消除二次解析属于「顺带的优雅」，不应作为本提案的主要理由。
  • 语义难题：L2/L3（按标题文本或位置猜测）可能猜错。因此必须把「猜」的结果显式标注为低置信度，而不是伪装成精确命中——这正是「协商」原则的要求。

07落地路径

不必推倒重来。四个阶段，每一步都独立交付价值，且可随时停下。

阶段 A

加审计器（不动任何结构）

在流水线末端统计「目录条目 → 产出章节」的映射覆盖与「文档区间」覆盖，不平账即报。这一步就能抓住今天这个 bug。

收益：立刻获得安全网 · 风险：极低
阶段 B

引入对齐阶梯 L0–L4

不改变层间边界，只在切分器内逐级尝试，并把「达成层级」写入 diags 与结果上报。

收益：粒度不再无声蒸发 · 风险：低
阶段 C

选区模型

切分器产出 {file, range} 而非字符串；转换器接受「文档 + 选区」。消除二次解析，让上下文不再丢失。

收益：无损 + 只解析一次 · 风险：中（要重构层间契约）
阶段 D

溯源进入产出

每篇笔记携带来源坐标与对齐层级，可在 frontmatter 或报告中可见：「本章由标题文本匹配得出，置信度中」。

收益：用户可判断可信度 · 风险：低

08可验证的判据

一个哲学提案若不可证伪，就只是修辞。这条判据可以机器校验：

守恒判据

对任意输入 EPUB：正文覆盖率必须 = 100%，否则必须给出带理由的豁免清单（如 <script>、远程图片）；

每个目录条目必须映射到一个产出单元，未映射者必须显式登记原因；

且全书必须上报一份对齐层级分布（L0–L4 各占多少）。

三条中任意一条不满足 → fatal，而不是 warning。
